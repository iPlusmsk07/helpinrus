ПОМОГАЙ — БЕЗОПАСНАЯ СБОРКА

СТАТУС ВЕРСИИ
- Вход, сессии и восстановление пароля реализованы через собственный same-origin
  API; на production они считаются готовыми только после настройки SMTP и
  успешного end-to-end теста. Сторонний browser-auth runtime не используется.
- Профили, публикации и чаты нужно перенести на новый backend отдельно; до этого UI
  явно сообщает, что раздел временно недоступен.
- Карта работает через Яндекс Карты.
- Реальные платежи, KYC, загрузка паспортов, жалобы и поддержка не подключены.
- Интерфейс явно сообщает об этом и не имитирует успешную отправку документов.

ПРОВЕРКА ПЕРЕД ПУБЛИКАЦИЕЙ
1. Установить Node.js 20 или новее.
2. Выполнить установку зависимостей по lock-файлу.
3. Запустить: pnpm test
4. Запустить: pnpm build
5. Проверить, что в www находятся только публичные web-файлы.

GITHUB И PRODUCTION
- Единственный источник production-кода — ветка main GitHub-репозитория helpinrus.
- Сборка: node scripts/prepare-www.mjs
- Публичный каталог сборки: www
- SQL, README, package.json и внутренние документы не публикуются.
- После merge защищённый deploy на 201.51.4.212 запускает тесты, собирает www и
  атомарно переключает /var/www/helpinrus на новый релиз.
- Production нельзя менять в обход GitHub и повторяемого deploy-скрипта.

PRODUCTION SSH
- Сервер: 201.51.4.212
- Пользователь: root
- Подключение: ssh root@201.51.4.212 (аутентификация по SSH-ключу)
- Каталог сайта: /var/www/helpinrus
- Приватные ключи и другие секреты в репозитории не хранятся.

AUTH BACKEND
- Исходники API находятся в server/, повторяемая установка — в ops/.
- База SQLite и секреты не попадают ни в Git, ни в папку www.
- Для реальной доставки reset-писем нужен SMTP-отправитель, заданный только в
  /etc/helpinrus/auth.env на production-сервере. Подробности: ops/README.md.

ВНЕШНИЕ ПРОВАЙДЕРЫ ВХОДА
- Кнопки Яндекса и Госуслуг не имитируют успешный вход и остаются выключенными до отдельного
  серверного OAuth-подключения.

ВАЖНО
- SMTP-пароль, APP_SECRET, база и резервные коды запрещено хранить в репозитории.
- До подключения KYC нельзя принимать паспортные и профессиональные документы.
- До подключения серверной платёжной логики нельзя считать демо-бонусы деньгами.
