# Безопасность проекта «Помогай»

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости, ключи, токены, пароли, персональные данные или снимки экранов с секретами в публичном GitHub Issue.

До появления выделенного защищённого канала владельцу проекта следует получать сообщения об уязвимостях только через заранее согласованный личный канал. В сообщении достаточно указать затронутую функцию, безопасные шаги воспроизведения и возможные последствия. Реальные данные пользователей использовать нельзя.

## Поддерживаемое состояние

Публичная версия `0.9.3` является прототипом. Она не предназначена для платежей, паспортных данных, результатов проверки личности или других чувствительных данных. Функции, которым нужен защищённый серверный процесс, должны оставаться недоступными до отдельной реализации и проверки.

## Правила для репозитория

- секреты и резервные коды не хранятся в Git, документах и Deploy Preview;
- изменения проходят отдельную ветку, Pull Request, автоматические проверки и Deploy Preview;
- SQL сначала проверяется в отдельном тестовом проекте Supabase;
- production, `main` и живая база не изменяются без отдельного явного решения владельца;
- найденный секрет считается скомпрометированным и заменяется, даже если его быстро удалили из файла.
