# Максимальная защита аккаунтов проекта

Этот список выполняет владелец вручную. Пароли, коды и снимки recovery codes нельзя присылать в чат или добавлять в репозиторий.

## Общие правила

- Для GitHub, production SSH, Supabase и почты используются разные случайные пароли длиной не менее 20 символов.
- Пароли хранятся только в системном менеджере паролей.
- Основной второй фактор: passkey или аппаратный ключ. Приложение-аутентификатор используется как резерв.
- SMS не используется как единственный второй фактор.
- Recovery codes распечатываются или сохраняются в отдельном зашифрованном хранилище; не рядом с основным паролем.
- В каждом сервисе удаляются неизвестные сессии, приложения и токены.

## GitHub

- Включить 2FA и добавить минимум два независимых способа восстановления.
- Добавить passkey; recovery codes сохранить офлайн.
- Проверить `Settings -> Applications`, `Sessions`, SSH keys и personal access tokens.
- В репозитории включить Dependabot alerts/updates, secret scanning и push protection, если доступны.
- Защитить `main`: обязательный Pull Request, успешная проверка `Security and quality`, запрет force push и удаления ветки.
- Запретить Actions получать лишние права; workflow этого аудита использует только `contents: read`.

## Supabase

- Включить MFA аккаунта и сохранить recovery codes.
- Проверить участников организации: оставить только нужных владельцев.
- В `Access Tokens` удалить временные и неиспользуемые токены.
- Перед публичным запуском включить CAPTCHA/anti-bot и проверить ограничения частоты регистрации и писем.
- Установить серверную политику паролей не слабее интерфейса: минимум 12 символов; предпочтительны случайные пароли из менеджера.
- Никогда не размещать `service_role` key в браузере, каталоге `www` или GitHub.
- Если ключ попал в чат/скриншот/репозиторий, немедленно заменить его.
- Настроить регулярный зашифрованный backup. На Free plan автоматический backup отсутствует.

## Production-сервер

- Входить только по SSH-ключу; парольный вход root отключить.
- Разрешить публикацию только из защищённой ветки `main` через повторяемый deploy-скрипт.
- Хранить серверные секреты только в `/etc/helpinrus/auth.env` с минимальными правами.
- Проверять `nginx -t`, systemd-журналы, локальный health endpoint и публичный HTTPS после каждого релиза.
- Ограничить участников GitHub и SSH-ключи сервера; удалить неиспользуемые токены и ключи.

## Почта и устройство

- Почтовый аккаунт защищён passkey/2FA, потому что через него восстанавливаются остальные сервисы.
- На Mac включены FileVault, автоматические обновления, блокировка экрана и Find My.
- Резервный зашифрованный DMG хранится минимум в двух независимых местах.
- Один раз в квартал проводится ревизия токенов, участников, recovery codes и тест восстановления backup.

## Что нельзя делать

- не хранить пароли в обычных заметках, текстовых файлах или таблицах;
- не пересылать коды авторизации в чат;
- не давать одному токену бессрочные и максимальные права;
- не использовать живую базу для экспериментов с SQL;
- не запускать тесты записи против production-базы: для них нужен отдельный тестовый контур.
